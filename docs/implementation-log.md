# Implementation log: post-processor plugin system

What each phase of `docs/post-processor-spec.md` did, what it found, and what the next phase has to know. Newest at the end.

## Phase 0: golden files (commit f7f8d53)

Freezes today's G-code (v0.7.6) so that phases 1–2, refactors that must change no output, can prove it.

- **Matrix** (`tests/golden.rs`, module `matrix`; files in `tests/golden/`, described in `tests/golden/README.md`): 6 projects
  (`examples/projects/oval-sign` and the 5 built-in samples: name plate, box, relief, shaped relief, oval) × 5 dialects
  (GRBL, grblHAL, FluidNC, Mach3 / LinuxCNC, Marlin) × mm / inch × arcs off / on. Each case is written the way
  `putia-gcode -o` and File → Export write it: `pieces::generate_parts` with the summary header from `summary::add_header`, and
  also `split::generate_files` per tool where that makes more than one file. Every `.nc` has a `.notes.txt` with
  `Output.notes`. 280 + 280 files, 27.2 MB.
- **Byte-exact** comparison; a mismatch prints the file, the first differing line with context, expected and actual. A stale
  or missing file fails. `UPDATE_GOLDEN=1 cargo test --test golden` rewrites them.
- **Fixed machine**, so nothing depends on the local setup: the app's default machine, 300 × 200 × 60 mm, rapid 2000 mm/min,
  safe Z 5 mm, spin-up 2 s, no line numbers, G54 (the project's own `job.wcs`), no machine limits. Sample tool ids pinned.
- **Deterministic** over two runs, one and many test and rayon threads, another locale, and a regenerate.
- The 8 older GRBL snapshots in `tests/data/*.snapshot.nc` (`UPDATE_SNAPSHOTS=1`, with a coordinate tolerance as fallback)
  stay as they were.

## Phase 1: the IR inside the emitter

The emitter (`struct Em` in `src/toolpath.rs`) no longer writes text. It pushes events into a `Program` (new `src/program.rs`),
and a canonical renderer (new `src/program/render_canonical.rs`) writes the program as today's text. Gate: no golden file
changed after step 0 (`git diff --stat bb175ff -- tests/golden tests/data` is empty).

### Step 0: the golden gaps, closed first (commit bb175ff)

The phase 0 files never reach some emitter paths (none of the 280 contains them). Before any refactor, option cases were added

| `opt-start-end-code-numbered` | numbering runs after the start and end lines are inserted |

| `pause` | `tests/data/hardware_m0_aircut.project.json`: a pause with the spindle running; a pause that ends a per-tool file |
| `pen` (mm and inch) | `tests/data/hardware_pen_test.project.json` with a 0.125 s pen-down dwell: `select_pen`, `draw_op`, `G4 P0.13`, a pause with no spindle running; inch because the draw comment has units |

The option cases use a small two-tool job made in code, so they stay small. `tests/data/relief-ledges.project.json` was not

Two Marlin quirks are now frozen as they are (not changed by phase 1): the pen dwell is written as `G4 P..` on Marlin, and a
`-plug` file's header keeps "Stock" on Marlin (`pieces.rs` looks for `(Stock ` after the renderer turned it into `; Stock`).

### What moved where

- `src/program.rs` (new): `Program { meta, events }`, `Meta`, `Event`, `CommentKind`, `DwellWhy`, `ToolRef`, `Xyz`, `Dialect`.
  `Event::halts` is the rule for `Move.stop` (below).
- `src/program/render_canonical.rs` (new): `render(&Program) -> Rendered { lines, source, troch_arcs, arcs }` and `base()` (the
  events as text, before fitting). Everything that formats a G-code word: units and decimals, `G0`/`G1` words, the setup
  block, `T# M6`, `M3 S`, `M5`, `G4 P`, the three stop forms, the end, arc fitting, start/end code, Marlin's `;` comments, line
  numbers. `number_lines`, `stop_line`, `marlin_stop`, `stop_message` and `marlin_comment` moved here from `toolpath.rs`; the
  first four are re-exported at `toolpath::` (their old paths). `num`, `to_fixed` and `tool_label` stay in `toolpath.rs`.
- `src/toolpath.rs`: `Em` holds `ev: Vec<Event>` instead of `g: Vec<String>`. `go()` keeps the decision of which axes a move
  writes (raw comparison with `cur`, as before) and whether the feed is written, and stores the values in work mm
  (`x - ox`, `y - oy`, `z + zt`); `rapid()` and `feed()` replace `go("G0", ..)` and `go("G1", ..)`. New small helpers:
  `comment`, `op_comment`, `stop`, `tool_change`; `spindle_on`, `spindle_off`, `spin_wait` push events. `generate()` builds
  the `Program`, renders it, adds the arc and start/end notes from the render, runs `verify::hazards` on the final lines and
  returns `Output { lines, program, .. }`. `op_pause` lost its unused `mach` parameter. The move list, times, tool-change
  bookkeeping, tab marks and the speed cap stay where they were computed.
- `src/arcs.rs`: `fit_arcs_mapped` (the same text as `fit_arcs`, plus the input line of each output line); `fit_arcs` wraps it.
- `Output` gains `pub program: Program` (`tests/timing.rs` builds an `Output` literally and sets it).
- The four tests of the dialects' text (line numbers, start/end code, Mach3, Marlin) moved from `toolpath.rs` to the renderer
  (`render_canonical.rs`, module `generated`), unchanged.

### Events and the lines they write

Every line of today's output comes from one event (or from the machine's start/end code, which has no event). The renderer
takes the dialect, units, work offset, line numbers, arcs and the start/end code from `Meta`.

| Today's line(s) | Event | Notes |
|---|---|---|
| `(PutiaCNC - GRBL)`, `(Stock … )` | `Comment { kind: Info }` | text without brackets; the renderer adds them |
| GRBL: `G21 G90 G17 G94 G54`; Mach3: `G21 G90 G17 G94`, `G40 G49 G80`, `G54`; Marlin: `G21 G90` and its two comments | `Setup` | units, WCS and dialect from `Meta`; Marlin's two operator comments are part of its setup block |
| the first `G0 Z…` (written by hand) | `Rapid { to: z }` at `meta.start_at` | no `Move` |
| `G0 …` / `G1 …` | `Rapid { to }` / `Feed { to, feed, write_feed }` | `to` holds only the axes written; `G1 F800` alone is a `Feed` with no axis |
| `(Pass n)`, `(Pass n, levelling lap)` | `Comment { kind: Pass }` | |
| `(Operation k: …)`, `(Repeat i of n)` | `Comment { kind: Operation }` | |
| `(Pen: the spindle stays off)` | `Comment { kind: Info }` | |
| `(Tool: name)` / `T# M6 (Tool #: name)` | `ToolChange { tool }` | Mach3 writes the `T` line, the others the comment; the name made plain ASCII by the renderer (`tool_label`) |
| `M3 S…` | `SpindleOn { rpm }` | |
| `M5` | `SpindleOff` | |
| `G4 P2` (spin-up) | `Dwell { why: SpinUp }` | written as given |
| `G4 P0.13` (pen-down dwell) | `Dwell { why: Requested }` | two decimals (`to_fixed(s, 2)`) |
| `M0 ; msg` / `M0 (msg)` / `M0 msg` | `Stop { message }` | GRBL family / Mach3 / Marlin (`marlin_stop`) |
| final `M5` (or Marlin's stop) | `SpindleOff` (or `Stop`) | |
| `G0 X0 Y0` and `M2` / `M30` / `(End of program)` | `ProgramEnd { park: X0 Y0 }` | two lines; the park has no `Move` |
| `G2` / `G3` | — | fitted on the text by the renderer; an arc line maps to the first event of the run it replaces |
| start / end code | — (`Meta.start_code`, `end_code`) | source `None` |

Renderer order, as the generator had it: events → arc fitting (with arcs off: only the trochoidal ranges, from the back; with
arcs on: everything) → start code before the event at `start_at`, end code before the last line → `marlin_comment` over all
lines → `number_lines`. The trochoidal ranges were line ranges; they are event ranges now (from 8 events before the loops, as
it was 8 lines), mapped to lines through the source map. In the program body every event is one line before fitting, so the
ranges are the same lines; only the setup block has more than one line, and if a range ever reached back into it, the
extra lines would be header and setup lines without X or Y, which the fitter passes through and which do not move its
position.

Rounding: the renderer divides the stored work-mm value by the units factor and rounds with `to_fixed`, the same floating-point
steps as `go()` did (`(x - ox) / ku`, `(sz_init + zt) / ku`, `fd / ku`).

### `Move.stop`: the event rule

Old rule (text): a move starts from rest when a line written since the previous move (from the first line, for the first move)
starts with `M`, `G4` or `T`.

New rule (events, `Event::halts`): a move starts from rest when an event since the previous move is `SpindleOn`, `SpindleOff`,
`Dwell` (either kind), `Stop`, or a `ToolChange` on Mach3 / LinuxCNC (where it is a `T# M6` command; elsewhere it is a comment
and the `Stop` before it is what halts). The two differ in one place only: Mach3's setup line `G40 G49 G80` starts with `G4`,
so the old rule counted the setup as a halt before the first move. On Mach3 a `ToolChange` (`T1 M6`) always stands between
the setup and the first move, so the result is the same.

Proof while working: a temporary `program::legacy_move_stops` recomputed the old rule from the rendered text and was asserted
equal to `Move.stop` for every output of the golden tests (every matrix and option case, every split and plug file, the 8
snapshots) and for random projects (`tests/random_projects.rs`, each project in all 5 dialects, mm and inch; 20 seeds in
the normal run, and 400 seeds in a release run: 394 projects generated, 6 refused with a message, so about 3,900 programs). A mutation (a tool change never halts) made the Mach3 pen cases fail. The helper and
the assertions were removed before the phase was finished.

### Deviations from the spec's IR

- `Meta` holds what the renderer needs today: `dialect`, `units`, `wcs` (already resolved by `Job::wcs_name`), `numbered`,
  `arcs`, `start_code`, `end_code`, `start_at` (event the start code goes before) and `troch` (event ranges of trochoidal
  loops). It has no job name, stock, machine id or used tools yet.
- `Event::Setup` is not in the spec: the setup block after the two header comments (the spec's `on_open`).
- No `OperationStart` / `OperationEnd`: operation text is a `Comment { kind: Operation }`. Phase 2 needs the markers for
  `on_section`; the place is the operation loop in `generate()`.
- `ToolChange` has no `next`. `ToolRef.number` is `u32`, the order of first use (as `select_tool` numbered tools);
  `length_offset` is always `None`; `name` is the raw name.
- `SpindleOn` has no direction (always `M3`).
- `Feed` has no `kind`, and has `write_feed`: the emitter's modal feed rule stays in the emitter (it forgets the feed at every
  `select_tool`, `select_pen` and `op_pause`, even when they write nothing, so a renderer cannot rebuild it from the events).
  A `Feed` can have no axis (`G1 F800`).
- No `Arc` event: arcs are still fitted on the text, in the renderer (spec: "until the port matches today's output exactly").
- `Xyz` is three numbers and a mask with accessors (`x()`, `y()`, `z()`, `get(i)`), not three `Option<f64>`, so an `Event` is
  48 bytes instead of 64.
- `Stop.optional` is always false; `CommentKind::Warning` is not used yet.
- `render()` returns the arc counts (for the notes) instead of `Rendered.extension`, `line_ending` and `notes`; the notes are
  still written by `generate()`. `Output` does not keep the source map yet.

### Dialect decisions still in the generator (phase 2's `Caps` to-do)

What left `Em` is the formatting of G-code words. These choices of *which events* to emit still depend on the dialect:

1. Spin-up wait: none on Marlin (`Em.spin` is 0) → `caps.dwell` / `caps.spindle`.
2. `spindle_on`: Marlin gets `Stop("Start the spindle at N rpm, then resume")` instead of `SpindleOn` → `spindle = Manual`.
3. `spindle_off`: nothing on Marlin → `spindle = Manual`.
4. Tool change (`select_tool`, `select_pen`): a `Stop` with the change message before `ToolChange`, except on Mach3 / LinuxCNC;
   Marlin's message starts "Stop the spindle and change tool…" → `tool_change = Manual | Atc`, `spindle`.
5. `op_pause`: on Marlin, with the spindle used, the message gets "Stop the spindle. " in front → `spindle = Manual`.
6. Program end: Marlin gets `Stop("Stop the spindle, then resume")` instead of `SpindleOff` → `spindle = Manual`.
7. The first comment names the dialect (`(PutiaCNC - GRBL)`).
8. The work offset is resolved by `Job::wcs_name` (Mach3 has 9 systems, Marlin 1, the others 6) → `caps.wcs_count`.
9. `Move.stop` counts a `ToolChange` as a halt on Mach3 only → follows `tool_change = Atc`.
10. Tool numbers are the order of first use on every dialect (only Mach3 writes them) → phase 3's tool table.

The `mach` flag still runs through `relief_op`, `photo_op`, `draw_op` and `rest_pass` only to reach `select_tool` and
`select_pen` (item 4); `Em` keeps `marlin` (items 1–3, 5, 6) and `mach` (item 9). Not a dialect branch, but worth knowing:
the pen-down dwell is a `G4` on every dialect, Marlin included.

### `program` and `lines` differ after summary, split and pieces

`summary::add_header` (the summary comments at the top, and renumbering when the job is numbered), `split::generate_files`
(`(File i of n …)`, `(Before you start…)`, `(After this file: …)`) and `pieces::generate_parts` (`(Stock` → `(Plug piece`,
`[replaces the main stock…]`) still edit `Output.lines` afterwards and leave `Output.program` as the generator made it. So for
every output of `generate_parts` and `generate_files` (which always add the header), `lines` holds more than
`render(&program)` writes, and the line indices differ. Phase 2/4: those texts become events (or the post renders them), so
that `lines`, `program` and the source map agree again.

### Timing

Release build (LTO), this 4-core container, `cargo run --release --example gen_time` (new, `examples/gen_time.rs`): the
time of `generate()` alone, before (step 0, bb175ff) and after, two rounds of 9 (5 for the big one) runs each.

| Program | Before | After |
|---|---|---|
| sample-shaped-relief golden case (GRBL, mm, arcs off): 7,541 lines, 7,225 moves | median 0.129 / 0.132 s (min 0.127 s) | median 0.128 / 0.132 s (min 0.126 s) |
| `BUSY=60`, the pocket of 60 circles of `gui/src/perf.rs`: 1,051,919 lines, 1,049,748 moves, arcs off | median 1.536 / 1.480 s | median 1.382 / 1.365 s |
| the same with arcs on (196,343 lines) | median 1.850 s | median 1.702 s |
| `Output.clone()` of the big one | median 0.081 s | median 0.110 s |
| `Output.clone()` of the shaped relief | 0.4 ms | 0.5 ms |

The shaped relief is all geometry; the emitter's share does not show. On a million moves the emitter is a little faster
(the renderer writes the words into one buffer; `go()` used to build each word with its own `format!`). The cost is memory:
an `Event` is 48 bytes, so the program adds about 50 MB to the 1M-move output (beside about 92 MB of moves at 88 bytes and
the text), and cloning it takes 30 ms more. The GUI clones the output once per finished generation (for the checks thread)
and for the setup sheet; if that ever matters, `Output.program` can become an `Arc<Program>`.

### Traps for phase 2

- Keep the rounding order: work mm → divide by the units factor → `to_fixed` → `num`. Converting earlier changes digits.
- Do not rebuild the move list from the events without skipping the first lift (`meta.start_at`) and the park: they have no
  `Move`. A `Feed` with no axis has a zero-length `Move`.
- The emitter's feed rule (`write_feed`) is not modal on values: it forgets the feed at every tool selection and pause.
- Arc fitting depends on the exact text (3 or 4 decimals, the feed word on the first line of a run, I/J rounded by
  `arcs::fixed`, written by `arcs::txt`, which are not `to_fixed` / `num`). An IR fitter must reproduce that before the text
  fitter goes.
- The start code goes in before the event at `start_at`, after fitting; the end code before the last line (after the park,
  before `M2` / `M30` / `(End of program)`); both before Marlin's comment rewrite and numbering.
- `marlin_comment` rewrites every whole-line `(…)`, including the machine's start/end code, but not the summary header, which
  is added after `generate()`: Marlin files have a bracketed header today (frozen in the goldens).
- `pieces.rs` and `summary::describe` find the stock comment by its text (`(Stock `), which fails on Marlin: the `-plug` header
  keeps "Stock" (above) and a Marlin summary has no "Zero" row. Both frozen in the goldens.
- Mach3's `G40 G49 G80` starts with `G4`: anything that reads the text by prefix must not take it for a dwell.
- `summary::describe` reads the text (the `M3` line and the `G4` after it, `M0` messages, the last 6 lines): a post that changes
  those words changes the summary.
